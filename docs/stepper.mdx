---
title: Stepper
description: A declarative, validation-aware multi-step wizard for Ink.
---

`Stepper` mounts only the current `Step`. Each step can block progression
with a synchronous or asynchronous `canProceed`, and callers can control
navigation through `useStepper` or render-prop context.

```tsx
import { Text } from "ink"
import { Step, Stepper, StepperNavigation } from "@kud/ink-ui"

<Stepper
  onComplete={() => save()}
  onCancel={() => close()}
  onStepChange={(index) => trackStep(index)}
>
  <Step name="Details" canProceed={() => validateDetails()}>
    {({ goNext }) => <Text>Fill in details, then call goNext()</Text>}
  </Step>
  <Step name="Review">
    {({ goBack, goNext }) => (
      <>
        <Text>Review and confirm</Text>
        <StepperNavigation />
      </>
    )}
  </Step>
</Stepper>
```

## Navigation

`goNext()` checks `canProceed` and `onExitStep`. `goBack()` and
`goTo(index)` skip `canProceed` but still call `onExitStep`.
Returning `false` from `onExitStep` vetoes a transition; thrown errors
appear below the step and are forwarded to `onError`. Calls are locked
while async validation is in progress. Navigating beyond the last step
invokes `onComplete`, while going back from the first invokes `onCancel`.

`step` makes the position controlled; without it, `initialStep` selects
the starting index. `onStepChange` reports requested transitions for both
modes. Use explicit React keys when conditionally inserting or reordering steps.

**Keyboard ownership:** `keyboardNav` is **false by default**.
Enable it only if no nested input claims Enter. It handles Enter to advance;
it **does not bind** Escape, Backspace or `q`. Those belong to the host's
single `useAppKeys`. In the host's back handler, call `goBack()` (or
`cancel()` to cancel directly); disable the Stepper's Enter shortcut while
a text field owns input.

## Progress and design tokens

The built-in `StepperProgress` uses ink-ui's existing `colors.success`,
`colors.accent` and `colors.muted`, along with the exported `symbols`
for completed, active and pending states. A shape always carries status,
even on monochrome terminals.

Set `showProgress={false}` to hide progress or pass
`renderProgress={(props) => <StepperProgress {...props} orientation="vertical" />}`
for a custom layout. Pass `ascii` on `Stepper` or `StepperProgress`
to use `asciiSymbols` in progress indicators.

Validation failures render via ink-ui's `StatusMessage variant="error"`,
and `StepperNavigation` uses its `FooterHints` presentation. Hints never
bind keys; the host owns the Back action.

See [Design Tokens](./design-tokens) for the expanded symbol, border,
and motion tokens.
